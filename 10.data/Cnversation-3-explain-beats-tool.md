Based on the resources available, the `beats` tool allows you to monitor and debug a running Filebeat instance. Here's a breakdown of what you can do with it:

*   **Inspect Configuration:**
    *   `filebeat/config.json`: You can view the current configuration of Filebeat.

*   **View Modules and Processors:**
    *   `filebeat/modules.txt`: Lists all the enabled and disabled modules in Filebeat.
    *   `filebeat/global_processors.txt`: Shows the currently configured global processors.

*   **Monitor Metrics:**
    *   `filebeat/metrics.json`: Provides global metrics for all Beats.
    *   `filebeat/input_metrics`: Gives you current metrics for all active Filebeat inputs, which is useful for seeing how much data is being processed.

*   **Access Logs:**
    *   `filebeat/logs`: Allows you to read the log files generated by Filebeat itself, which is essential for troubleshooting.

*   **Debug File Ingestion:**
    *   `filebeat/registry/log.json`: This is a powerful debugging tool. It shows you which files Filebeat is currently ingesting, their current read offset, and a flag for GZIP files. This is very useful to understand the state of file harvesting.
    *   `filebeat/registry/meta.json`: Shows metadata about the registry itself, like its version.

*   **Test Connectivity:**
    *   There is also a tool `filebeat-test-output` which allows you to test if Filebeat can connect to its configured output (like Elasticsearch or Logstash) using the current settings.

In short, the `beats` tool provides a comprehensive set of resources for inspecting the state, performance, and configuration of a Filebeat instance, primarily for monitoring and debugging purposes.
